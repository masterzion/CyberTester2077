# database

Database architecture and data reference: documented engines and versions, databases, schemas, tables or collections, fields and types, primary and foreign keys, relationships, indexes, constraints, defaults, and data lifecycle rules. Preserve ORM mappings, migration history and commands, seed procedures, transaction boundaries, concurrency behavior, connection pooling, and environment-specific requirements where documented. Include representative queries, query plans, measured performance, indexing decisions, maintenance, integrity checks, and troubleshooting with reproducible commands and their prerequisites. Distinguish the implemented schema from proposed changes and identify migration risks, compatibility requirements, and rollback limitations. Never invent tables, fields, data, performance claims, or successful migrations. Redact credentials and personal records; cross-reference drp.md for backup/restore, deploy.md for initial deployment, security.md for access controls, and implementation_plan.md for planned work rather than duplicating them.
